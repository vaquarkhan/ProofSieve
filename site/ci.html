Continuous integration

Run proofsieve check on pull requests and require the job. The composite action in this repository does that with go run, so the caller does not need a published binary.

name: proofsieve
on:
  pull_request:
jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: actions/setup-go@v5
        with:
          go-version: "1.23"
      - uses: vaquarkhan/ProofSieve/action@main
        with:
          base: ${{ github.event.pull_request.base.sha }}

A copy of this workflow is examples/github-workflow.yml. Fetch depth 0 is required so the base commit is present. The action writes evidence.json and uploads it as proofsieve-evidence, including when the check fails. The same report is the GitLab artifact in examples/gitlab-ci.yml.

Exit codes in CI

Exit 1 fails the job because the diff violated policy. Exit 2 fails the job because git, the policy, the lock, or a test command was unusable. Do not treat exit 2 as a pass. The report on stdout is Markdown unless you pass --format.

This repository

ProofSieve's own workflow runs go test ./... on Ubuntu and Windows and fails unless statement coverage is 100.0%. The Pages workflow publishes the site/ directory. The product's self-check is not required on the import commit; turn it on for later pull requests once a lock exists.
