Troubleshooting

The hook denies every write

Exit 2 with "scope lock is missing or invalid" means .proofsieve/scope.lock.yaml is absent or failed validation. Run proofsieve lock. A deny that names .proofsieve is intentional: humans edit that directory, then commit it.

check exits 2 before any finding

The message is prefixed by the failing step: policy, scope lock, or a git error. Confirm --base is a commit that exists in the clone, and that git is on PATH. Fetch the base with fetch-depth: 0 in Actions.

A bugfix fails the churn rule

Whitespace-only and rename-only lines count against max_nonfunctional_churn_pct. Mix a behavior change into the diff, or raise the percentage in the lock for that change. Formatting-only pull requests are supposed to fail a bugfix lock.

Mutation exits 2

test_command is empty, the command cannot be started, or a source file in the diff is missing from the worktree. The command is not a shell string. Pass ["pytest", "-q"], not "pytest -q".

Attestation does not satisfy CI

The comment sha must be the head commit ProofSieve resolved, not a branch name. The spec id must appear in the spec file. The test name must appear as an identifier in the repository and the following line must not skip the test. The comment author must be a human account.

Windows line endings

Git may check out CRLF when core.autocrlf is true. Locked digests are of the bytes on disk. Set the attribute you intend to hash, then regenerate the lock.
